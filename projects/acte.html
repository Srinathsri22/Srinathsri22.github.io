The Problem

No accountability between creative and media buying

The creative team delivers ad creatives to media buyers, but there was no reliable system to track: how many were actually tested, which ones won or lost, and whether fatigued creatives had been rotated.

This created a complete accountability gap between the creative and media buying teams. Creative-to-insight time was measured in days, and the feedback loop was entirely manual.

What I Built

Architecture (HLD v2)

GCP-native stack designed as a new module inside Adelevate:

  • Firestore for transactional state (write-heavy workflows, not suited for OLAP systems)
  • Google Cloud Storage (GCS) for creative asset storage
  • ClickHouse extension for metrics (additive to existing tables, not modifying them)
  • Dashboard-only feedback in MVP — no direct campaign modifications
  • Zero write access to scaling campaigns (hard boundary)

Scope Boundary Enforcement

Hard separation between test campaigns and scaling campaigns enforced via campaign-name prefix regex (ACTE_TEST_<vertical>_...) at the connector layer. This is enforced at the code level, not by convention or trust.

Design Decision

Adelevate's existing rules engine ignores ACTE-prefixed campaigns automatically. The boundary is architectural, not procedural.

Phased Build Plan

  • Phase 1 (Weeks 1–6): Read-only. Intake UI, dashboard, verdict computation on existing ads. Validates logic before automation.
  • Phase 2 (Weeks 7–10): Meta automation. Test Orchestrator, auto-pause losers, auto-graduate winners.
  • Phase 3 (Weeks 11–14): Multi-platform (Snap, TikTok). Fatigue detection. Full lifecycle.
Key Design Decision

LLD deliberately deferred until the dev team reviews the Adelevate codebase. Rationale: specs built without engineers reviewing the actual codebase don't get trusted or followed.
